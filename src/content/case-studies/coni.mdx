## Problem

AI 에이전트와 협업하면서 반복적으로 부딪히는 구조적 한계가 있었습니다.

- **세션 휘발성**: 대화가 끊기면 작업 맥락이 사라져 매번 처음부터 다시 설명해야 했습니다.
- **단일 에이전트 한계**: 하나의 AI만 쓸 수 있어 복잡한 작업을 분업하거나 병렬로 처리할 수 없었습니다.
- **프로젝트 기억 부재**: 과거 커밋, 설계 판단, 코드 의존성, 테스트 관계가 AI에게 구조화된 맥락으로 전달되지 않아 동일한 실수가 반복되었습니다.
- **프로젝트별 맞춤 부재**: AI가 프로젝트의 기술 스택, 컨벤션, 도구 환경을 모른 채 일반적인 답변만 제공했습니다.

## Role

개인 프로젝트로 기획, 아키텍처 설계, 전체 개발을 담당했습니다.

- **작업 추적 파이프라인 설계**: Objective → Workplan → Commit 3계층 구조를 정의하고, idle → breakdown → execute → verify → complete 5단계 phase를 ObjectiveRunner가 자동 진행하도록 구현했습니다.
- **멀티 에이전트 오케스트레이션**: tmux 기반으로 Claude, Gemini, Codex 등 여러 CLI 에이전트를 동시 실행하고, architect, worker, critic, supervisor 역할별 프롬프트 라우팅과 execute lane 관리를 구축했습니다.
- **온톨로지 기반 프로젝트 메모리**: `memory_nodes`와 `memory_edges`로 코드·문서·커밋·작업 단위를 통합하고, 임베딩 검색과 관계 그래프를 함께 쓰는 메모리 계층을 구현했습니다.
- **하네스 엔지니어링**: 7단계 자동 분석(스택 → 도메인 → 컨벤션 → 도구 → 가이드 → 설치 → 스킬 적용)으로 어떤 프로젝트에든 CONI를 맞출 수 있는 체계를 설계했습니다.
- **DB 이중화와 마이그레이션**: SQLite(로컬)와 Supabase(원격) 두 백엔드를 지원하고, 동일한 온톨로지 제약을 양쪽 DB에 생성해 개인 사용부터 팀 공유까지 대응합니다.

## System

| 구분 | 기술 |
|------|------|
| **언어** | TypeScript |
| **런타임** | Node.js |
| **데이터베이스** | SQLite (로컬) + Supabase (원격) |
| **오케스트레이션** | tmux 세션 기반 멀티 에이전트 |
| **메모리 DB** | `memory_nodes` + `memory_edges` 통합 지식 그래프 |
| **온톨로지** | manifest 기반 node/edge vocabulary, 증거·origin·strength 정책 |
| **검색** | 임베딩 벡터 검색 + PostgreSQL FTS + 리랭커 |
| **CLI 프레임워크** | Commander |
| **VCS 연동** | `coni commit` 기반 커밋·임베딩·관계·코드 그래프 동기화 |

### 기술적 도전과 해결

- **세션 연속성**: 모든 작업 상태를 DB에 기록하고, `coni status`가 현재 phase와 `next_steps`를 안내합니다. 새 세션에서도 Objective, Workplan, Commit, lane 상태를 근거로 이어갈 수 있습니다.
- **에이전트 비종속성**: 특정 AI에 종속되지 않도록 에이전트 추상화 계층을 설계했습니다. Claude, Gemini, Codex 또는 향후 어떤 CLI 에이전트든 동일한 인터페이스로 연결됩니다.
- **온톨로지 제약**: `imports`, `calls`, `tested_by`, `implements`, `co_changed`, `similar` 등 15종 edge의 허용 source/target, 증거 출처, origin, strength 범위를 manifest에 정의하고 PostgreSQL/SQLite 트리거로 생성했습니다.
- **자동 메모리 복구**: `coni memory backfill`이 누락 커밋, 임베딩, auto relation, graph refresh, stale strength를 자동 진단·복구하도록 정리했습니다.
- **비정상 상태 감지**: 고아 Workplan, 미연결 커밋, 상태 드리프트, handed-back lane 이상 등을 감지하고 복구 경로를 안내하는 체계를 구현했습니다.

## Outcome

- **대화 세션이 끊겨도 작업이 이어지는** 영속적 협업 흐름을 구축했습니다.
- **5단계 작업 파이프라인**(idle → breakdown → execute → verify → complete)으로 개발 워크플로우를 체계화했습니다.
- **15종 온톨로지 edge vocabulary**로 코드 구조, 커밋 이력, 작업 의도를 하나의 그래프로 연결했습니다.
- **7단계 하네스 엔지니어링**으로 어떤 프로젝트에든 맞춤 적용 가능한 구조를 만들었습니다.
- **자동 메모리 backfill과 stale strength refresh**로 검색·그래프 품질을 유지합니다.
- **DB 이중화**(SQLite + Supabase)로 개인 사용과 팀 공유를 모두 지원합니다.
- 임베딩 기반 **시맨틱 검색과 온톨로지 그래프**로 프로젝트 맥락을 기계가 이해할 수 있는 형태로 축적합니다.

### 핵심 메트릭

| 항목 | 수치 |

### 이 프로젝트가 보여주는 것

이 프로젝트는 AI 협업의 핵심 병목이 모델 성능만이 아니라 **맥락의 연속성, 역할 분리, 기억의 구조화**에 있다는 가설을 검증한 사례입니다. 작업계획, 진행 상태, 커밋, 코드 관계를 온톨로지 그래프로 연결해 세션이 바뀌어도 작업이 이어지는 구조를 직접 설계·구현했으며, 반복 가능한 AI 협업 흐름이 실무 생산성의 기반이 된다는 확신으로 이어졌습니다.
